# 架构

本文描述 1a 数据层和 1b 看盘界面。离线训练骨架（`backend/supere/train/`，只读数据库）见 `docs/进度.md`；训练、特征和推理不在本文范围。

## 进程

```
币安公开行情（经可配置代理，默认 127.0.0.1:7890）
        |                         |
        | REST / vision           | WebSocket
        v                         v
   采集器进程  ----本机 WS:8767---->  API 进程 :8766
   （SQLite 唯一写者）                 （SQLite mode=ro）
        |
        +--> data/superE.sqlite（WAL）
        +--> data/raw/**/date=YYYY-MM-DD/*.parquet（zstd）
```

采集器启动时用操作系统文件锁锁住 `data/superE.lock`（Windows 上是 `msvcrt`，其它系统是 `fcntl`，都通过 portalocker）。锁不到就退出。PID 文件只用于停止脚本兜底，不拿来当锁。

API 只绑定 `127.0.0.1`。配置成其它地址会拒绝启动。需要写入的操作以后经 IPC 交给采集器，1a 还没有这类业务写入。

未收盘 K 线只放在采集器内存里，经 IPC 推给 API，再由 `GET /api/klines?include_forming=1` 或 `WS /ws/live` 给出。收盘（`x=true`）后才 UPSERT 进 `klines`。大约 60 秒后用 REST 再读一次，以官方值为准。

进程之间的 IPC 用本机 WebSocket，不用 ZeroMQ，少一个运行时。消息是 JSON，类型有 `kline`、`depth`、`aggTrade`、`forceOrder`、`markPrice`、`miniTicker`、`status`。API 发给采集器的 `{"type":"shutdown"}` 会让采集器退出。

## 数据源和接口版本

主数据是 U 本位 ETHUSDT 永续。现货 ETHUSDT 只录 1m。

合约 WebSocket 从 2026-04-23 起不能再用旧的 `/ws`、`/stream`。拆分公告日期是 2026-03-06。现在必须分成两条连接：

| 连接 | 地址 | 订阅 |
|---|---|---|
| market | `wss://fstream.binance.com/market/ws` | 15 个周期 `@kline_`、`@aggTrade`、`@markPrice@1s`、`@forceOrder`、`@miniTicker` |
| public | `wss://fstream.binance.com/public/ws` | `@depth20@100ms` |
| 现货参考 | `wss://stream.binance.com:9443/ws` | `@kline_1m` |

两类合约流不能放在同一个连接里。K 线推送最快大约 250ms，家用机实测中位大约 350–370ms，代码不假设固定间隔。盘口是每帧一份完整的 20 档快照，不是差分。

指数价 K 线 `GET /fapi/v1/indexPriceKlines` 的参数是 `pair`，不是 `symbol`。标记价和溢价指数 K 线用 `symbol`。这三类的 `limit` 上限是 1000（官方 connector 对 index/mark 的说明），普通 K 线仍是 1500。存档路径里的目录名仍然是 `ETHUSDT`，不受这个查询参数影响。

REST 根地址：

- 合约 `https://fapi.binance.com`
- 现货 `https://api.binance.com`
- 现货备用 `https://data-api.binance.vision`（只有现货。合约没有备用域名，连不上就告警，事后补）
- 存档 `https://data.binance.vision/data`

合约上线时间用的是 `exchangeInfo` 里的 `onboardDate=1574840700000`（2019-11-27）。

交易、账户、`listenKey`、`allForceOrders` 都在客户端里被拒绝。没有币安 key，请求也不签名。

## 存档起点

| 数据 | 起点 | 说明 |
|---|---|---|
| 合约 K 线月度 | 2020-01 | 月线文件夹叫 `1mo`，且只到 2023-06，所以 `1M` 不用它 |
| 合约 `1w` 月度 | 2020 起仍有文件 | 1a 仍按方案用 REST，因为总共只有几百根 |
| 资金费率 | 2020-01 | CSV 有表头：`calc_time,funding_interval_hours,last_funding_rate` |
| metrics | 2021-12-01 | `create_time` 是 `YYYY-MM-DD HH:MM:SS` 的 UTC 字符串，表示 5 分钟 bar 的起点。读入后排序 |
| 合约 aggTrades | 2019-12-31 | 默认不全量下载，只在长缺口时按天下载 |
| 现货 1m | 2017-08-17 | 2025-01-01 起时间戳是微秒，更早是毫秒 |
| bookDepth | 2023-01-01 | 是 ±1%…±5% 的累计深度，不是 20 档。1a 不导入，避免和自录盘口混用 |

新的 zip 带 CSV 表头，老的没有。解析时如果第一列不是整数就跳过。每个 zip 都下 `.CHECKSUM`，格式是 `sha256  文件名`，对不上就丢弃。

时间戳按位数归一成毫秒：16 位及以上当微秒，10 位及以下当秒。

## K 线边界

存的是毫秒时间戳，和时区无关。界面和日志用 UTC+8 显示。K 线不按 UTC+8 重切。

- 日线开盘是 UTC 00:00，也就是 UTC+8 08:00。收盘边界是次日 UTC+8 08:00。
- 周线开盘是周一 00:00 UTC。
- 月线开盘是每月 1 日 00:00 UTC。
- 3 日线不是从 Unix 纪元直接取模，而且相位在 2023 年 8 月换过。2020-01 到 2023-06 的存档开盘日满足 UTC 日序号 `% 3 == 2`（2020-01-02、01-05……）。2023-08-16、2023-12-08、2024-01-01、2024-01-04 满足 `% 3 == 1`。现在的「当前这根 K 线」按新相位算。缺口按库里相邻 `open_time` 判断，不拿旧相位去套 2023 年 8 月之后的日期，否则会把已有的新相位 K 线整段报成缺口。
- 周线仍是周一 00:00 UTC。月线仍是每月 1 日 00:00 UTC。

高周期直接存官方 K 线，不从 1m 聚合后当作官方值。1m 聚合只用来校验：价格必须完全相等，成交量相对误差不超过 `1e-6`。

## 存储

SQLite 表（和方案一致，只有两处名字改过）：

- `klines` 主键 `(market, symbol, interval, open_time)`。`market` 取 `um`、`um_mark`、`um_index`、`um_premium`、`spot`。价格和成交量用十进制字符串，避免浮点把「价格完全相等」比坏。
- `ingested_at` 是校准后的币安服务器时间，`ingested_local` 是原始本机时间。方案 5.5 要求本地时刻两边都留。
- `coverage.range_from` / `range_to` 对应方案里的 `from` / `to`。这两个词是 SQL 保留字。
- `um_metrics.ts` 存 bar 起点。REST 的 `timestamp` 比存档 `create_time` 晚 5 分钟（持仓量已在家用机对过），写入时减掉 5 分钟。其它 5 分钟比率接口按同一规则对齐。数值要到 `ts + 5 分钟` 才算已知，训练时再加一个周期的保守延迟。
- `funding` 只放已结算费率。预测费率在 `funding_live`，不写进历史表，避免训练和实盘口径不一致。
- `raw_coverage`、`stream_state`、`runtime_stats`、`app_events`、`signals`、`outcomes`、`models`、`jobs`。
- 消息面：`news`、`events`、`news_reaction`、`market_anomaly`，外加 `fear_greed`。恐慌贪婪指数的 `known_at = ts + 1 天`，训练时不能用指数当天的值。

Parquet 路径：

```
raw/aggTrades/um/ETHUSDT/date=2026-11-04/part-*.parquet
raw/depth/um/ETHUSDT/date=...
raw/forceOrder/um/ETHUSDT/date=...
```

日期是收到时刻的 UTC+8 日期。先追加 JSONL，大约每秒 fsync 一次，再转成 zstd Parquet。崩溃最多丢掉大约 1 秒。当天分片较多，或跨日后，会合并成 `part-000.parquet`。

训练侧用 DuckDB 内存库，以只读方式 `ATTACH` SQLite，并用 `read_parquet` 扫原始流。API 不提供任意 SQL。

## 限速和退避

合约预算是每分钟 2400 的 50%，现货是 6000 的 50%，`/futures/data` 是每 5 分钟 1000 次的 50%。真正发放时封顶在限额的 49%，这样自计峰值严格小于 50%。计数是本进程滑动窗口，不拿响应头当自己的用量。

响应头 `X-MBX-USED-WEIGHT-1M` 超过限额的 60% 时，本进程额度再减半。HTTP 429 按 1、2、4… 秒退避，最多 60 秒，连续 5 次后报错。HTTP 418 立刻停止该市场的 REST，并写 `app_events`（`REST_418`）。实时行情仍走 WebSocket。

K 线权重按 `limit`：小于 100 为 1，小于 500 为 2，不超过 1000 为 5，再大为 10。补洞用 `limit=499`。`aggTrades` 按保守值 20，这个数没有从官方原文核实，写在配置 `agg_trade_weight` 里。

每分钟把自计峰值和响应头写进 `runtime_stats`。验收只拿自计峰值和 418 次数做判断。

## 断线和重叠切换

异常断开：指数退避重连，然后用 REST 补 K 线和 aggTrade。盘口间隔超过 2 秒、以及强平在断线期间的空洞，写进 `raw_coverage`，不假装能补。

计划内重连：连接活过 `reconnect_hours`（默认 23）后，先连上新连接并订阅，新旧一起收。按盘口 `u`、逐笔 `a`、K 线 `(周期, open_time, E)` 去重。新连接连续收到 `overlap_confirm_messages` 条（默认 5，重复的也算）再关掉旧连接。超时 30 秒没收到数据就留下旧连接。

客户端每 20 秒发 ping。`ping_timeout` 放宽到 120 秒，避免一次短暂停顿被误判成断线。

## 时钟

启动时连续请求 `GET /fapi/v1/time`（默认 3 次），取往返最短的一次：

```
offset = serverTime - (t_send + t_recv) / 2
```

之后每 10 分钟再校一次。每次都写 `CLOCK_SYNC`。偏移变化超过 500ms 再写 `CLOCK_DRIFT`。绝对值超过 2 秒写 `CLOCK_SKEW`。校准失败写 `CLOCK_UNAVAILABLE`，偏移按 0 继续跑，不退出。

`recv_ms`、`ts_ingested`、`ingested_at` 用本机时间加 offset。原始本机时间在旁边一列。

## 代理

`httpx` 和 `websockets.connect(proxy=...)` 都显式使用配置里的代理。空字符串、`direct`、`off` 表示不走代理。同时设置 `NO_PROXY`，避免 API 和 IPC 被送进代理。websockets 17 默认会读环境变量里的代理，所以这里必须显式传入，不能依赖默认值。

## 消息面骨架

表已经建好。采集器是一个协议：`collect` 和 `healthcheck`，统一产出 `RawItem`。注册表里目前只有 Alternative.me 恐慌贪婪指数，而且默认不启用。在 `news.enabled_sources` 里写上 `alternative_me` 才会出网。

去重工具有 URL 的 SHA-256 和 64 位 SimHash（海明距离 ≤ 3 视为同一条）。Odaily、金色财经、RSS、日历是第二阶段的事，这里没有接。

异动检测用已经落地的行情，不依赖新闻：

- 放量：1 分钟成交额大于过去 60 根中位数的 5 倍，并且不低于过去 24 小时 1 分钟成交额的 P99。方案写的「同一时段」在 24 小时里只有一个同分钟样本，做不了分位，所以按这 24 小时里的全部分钟来算。
- 跳价：相对上一根收盘的变动大于 4 倍 ATR（ATR 只用更早的 K 线），或 10 秒内涨跌超过 0.5%。
- 强平：单笔名义价值 ≥ 100 万美元，或 1 分钟累计 ≥ 500 万美元。推送本身是抽样，只能当下限。
- 持仓量 5 分钟变化超过 3%，或预测资金费率绝对变化超过 0.0005。

命中后写入 `market_anomaly`，并带上前后 15 分钟的 `news.id`。

## 磁盘、备份

启动时和之后每分钟看数据目录所在盘的剩余空间。低于 50GB 写警告，低于 20GB 写错误。原始数据按方案永久保留，不在这里删除。

SQLite 用在线 `backup()`。Parquet 按清单做增量复制。每天 UTC+8 03:00 跑一次，并删掉超过 `keep_days` 的 SQLite 备份。`supere restore-drill` 把最近的备份复制到 `backups/drill` 做完整性检查。

## 界面

浏览器或 pywebview 只打开 `http://127.0.0.1:8766/`。开发时 Vite 在 5173，把 `/api` 和 `/ws` 代理过来。静态文件来自 `frontend/dist`，没有外链脚本。`dist` 不存在时，API 返回一页构建说明，窗口仍然能开。

实时通道是 `WS /ws/live`，大约每 250ms 一帧，内容是未收盘 K 线、刚收盘的 K 线、盘口（含数量）、最新成交、强平、标记价和状态。前端再做一次 250ms 上限的重绘合并。采集器每 250ms 把内存里的未收盘 K 线推给 API，这样逐笔成交对最后一根的改动能进界面，仍然不落库。

看盘指标里，KLineChart 自带的只作参考。ATR（Wilder）、VWAP（按 UTC 日重置）、CVD、OI、资金费率、多空比、主动买卖比、基差、溢价和清算额是前端自定义序列。OI 和多空比要到指标 bar 起点之后 5 分钟才画。资金费率只用已结算值，预测费率只出现在右侧，并写明不进历史。基差是合约收盘价减同一根时间内的现货 1 分钟收盘价，不用收盘之后的现货。清算额只读自录 Parquet 和当前内存，不回补。

这些自定义指标还不是训练特征。第二阶段用 TA-Lib 的同一套函数计算之后，界面改画后端的结果。

训练页的数据矩阵读 `coverage` 和 `raw_coverage`。1 分钟聚合校验走 `GET /api/checks/aggregate`，只读。回填、补洞和导出不从 HTTP 触发，因为那样会绕过「采集器是唯一写入方」。

`python -m supere preview` 用确定性的合成 K 线填一个单独的库，写完就关掉写连接，API 再以只读方式打开。预览不连币安，也不拿 `superE.lock`。

## 决策记录

1. **IPC 用本机 WebSocket。** 采集器已经依赖 websockets，API 也要向前端推流，不再加 ZeroMQ。
2. **自计权重封顶 49%。** 方案的预算是 50%，验收又要求峰值严格小于 50%。按 50% 打满会被判失败。
3. **空库不自动 REST 全历史。** 1 分钟从 2019 年补到现在会打满权重。全量走 `supere backfill` 的存档。
4. **逐笔全历史不进默认回填。** 日度 zip 大约十几 MB，几年下来是几十 GB。实时录，长缺口再按天下载。
5. **预测资金费率和已结算费率分开存。** 历史文件里没有预测值，混进同一张表会让训练看到实盘才有的数。
6. **bookDepth 存档不导入。** 它不是 20 档盘口。
7. **HTTP 418 不切换现货备用域名。** 备用域名是给连不上用的，不是用来躲开封禁的。
8. **1b 的看盘指标先写在前端，不引入 TA-Lib。** TA-Lib 的 Windows 轮子没问题，但训练特征要和第二阶段的截断测试一起做。现在 ATR 用与 TA-Lib 相同的 Wilder 平滑，并有公式测试。窗口用 pywebview，Linux 上没有 WebView2，桌面窗口要在 Windows 上确认。

## 已知限制

- 盘口和强平断了补不回来。
- 强平每秒最多一条，是抽样。
- K 线推送节拍不固定。
- metrics 的值在 bar 起点之后 5 分钟才可观察。
- 合约没有 `data-api.binance.vision` 这种备用站。
- `aggTrades` 权重 20 未从官方原文核实。
- 共享代理出口上的响应头包含别人的流量，不能拿来判定本进程是否超限。
