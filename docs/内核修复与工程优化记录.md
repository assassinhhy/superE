# superE 内核修复与工程优化记录

本文档记录对 `superE` 进行的 **7 项内核缺陷修复** 与 **4 项工程清理优化**，供后续功能开发与仓库维护参考。

## 二、工程清理与环境优化汇总

### 1. `.venv` 依赖对齐与全量测试跑通
- **问题**：`.venv` 缺失 `numpy`、`lightgbm`、`scikit-learn`、`scipy`、`cloudpickle`、`joblib` 等核心依赖，导致 `test_train_*`、`test_news_*` 无法运行。
- **处理**：在不终止运行中服务的前提下，使用 `uv sync --inexact` 补齐缺失依赖。
- **验证**：全量 `.venv/Scripts/pytest.exe` **全部通过**（`exit_code = 0`，0 failed）。

### 2. 根目录历史临时产物清理
- **处理**：清理项目根目录下的过期调试日志、临时脚本与探测 JSON（均为 `.gitignore` 已忽略的临时产物，未触碰 `data/`、`backend/`、`frontend/`、`tests/`、`scripts/`、`docs/` 及任何正式配置文件）。
- **统计**：共清理 **252 个** 临时文件/目录，释放磁盘空间 **150.46 MB**。

### 3. 代理硬编码统一收口
- **处理**：新增 `backend/supere/netproxy.py`（`DEFAULT_PROXY` 与 `resolve_proxy`），并在以下模块统一接入：
  - `backend/supere/news/scoring.py`
  - `backend/supere/news/live.py`
  - `backend/supere/hist/archives.py`
- **优先级**：环境变量（`HTTPS_PROXY` / `https_proxy` / `HTTP_PROXY` / `http_proxy`） > 显式传入的 `proxy` 参数 > 默认 `http://127.0.0.1:7890`。

### 4. 新增进程状态查看与一键停止入口
- **后端**：在 `backend/supere/spawn.py` 补充 `data/run/{role}.pid` 管理及基于端口（`8766`/`8767`/`8769`/`8770`）+ PID 的 `service_status`、`stop_services`（已处理中文 Windows `netstat` GBK 输出解码兼容）。
- **CLI**：`backend/supere/cli.py` 新增：
  - `supere status`：查看 `ingestor`、`api`、`board`、`news` 的 PID 存活与端口监听状态。
  - `supere stop [--role <role>] [--force]`：温和停止全部或指定后台服务。
- **脚本**：根目录新增 `停止superE.bat`。
- **测试**：`tests/test_cli_status_stop.py`（全 mock 测试，不触碰真实进程）。
